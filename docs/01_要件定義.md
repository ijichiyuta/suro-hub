## 1. 目的
- ユーザー(伊地知)個人専用の、**パチスロ期待値/ハイエナ立ち回りの「完璧な一次情報ハブ」**を作る。
- 既存2アーカイブ（**スマスロ期待値**=suroschool由来 / **スマスマ研究所**=slolabo由来）の情報を統合し、
  **重複を解消・出典を保ちながら、1機種1ページで探しやすく・読みやすく**する。
- 店内(ホール)で**オフライン・低電波でも高速**に、狙い目・期待値・解析・集計をすぐ引ける。

## 2. 対象ユーザー・利用シーン
- 利用者: 本人のみ（限定共有あり）。PINゲートで保護、検索エンジン非ヒット(noindex+robots)。
- 主シーン: **ホールで台の前** → 機種名で即検索 → 狙い目/期待値表/天井/ゾーンを数秒で確認、計算ツールで期待値算出。
- 副シーン: 自宅で解析・大量集計コラムをじっくり読む／稼働ロガーで収支記録／下振れ確認。

## 3. スコープ

- ツール群: 期待値計算・下振れシミュレーター・稼働ロガー（期待値サイト由来を統合）

## 4. ★最重要原則: 「情報は絶対に変えない」（Data Integrity 憲章）
リライトや統合で**数値・条件・解析・確率・期待値・サンプル数・設定判別・ゾーン/天井の数字が1文字でも変わってはならない**。
本プロジェクトの全工程はこの原則を最優先で満たす。守れない変換は**採用しない（原文を使う）**。

### 4.1 不可侵データ（絶対に触らない/自動生成物として原文保持）
- **表(table)全般**: 期待値表・ゾーン当選率・設定判別・機械割・スペック表 等 → **原文HTMLをそのまま搬送**（リライト対象外）。
- **計算ツールのデータ**(`labelList2` 等の埋め込み配列) → **原文のまま**。
- **数値トークン**: %・G(ゲーム数)・枚数・円・確率(1/xxx)・設定1〜6の値・期待値・回転数・天井/ゾーンのG数・サンプル数 等。
- **固有名**: 機種名・メーカー・モード名・役名・用語。

### 4.2 リライトしてよい範囲（表現のみ）
- 説明文・前置き・接続・冗長表現・誤字/表記ゆれ・見出しの言い回し。
- **事実・数値・条件・因果を追加/削除/改変しない**。「〜と思われる」を「〜だ」に断定強化するのも禁止（含意が変わるため）。

### 4.3 情報不変を保証する仕組み（自動検証ゲート・実装必須）
1. **原文の不変保存**: すべての原文(content.rendered)を `source-original/` に凍結保存。リライトは別レイヤー。原文はいつでも復元可能。
2. **抽出＆完全一致照合(before/after)**: リライト前後で以下を抽出し**多重集合として完全一致**を機械検証:
   - 全数値トークン（正規表現で %, G, 枚, 円, 1/xxx, 設定n, ○○G, n回 等を網羅抽出）
   - 全テーブルのセル値（表は原文搬送なので原理上一致するが二重チェック）
   - 機種名・メーカー・モード/役名などの固有名辞書との突合
3. **不一致=不採用**: 数値/データ集合が少しでも変わったリライトは**破棄し原文を採用**、`review-needed` にフラグ。**自動公開しない**。
4. **差分レビューUI/レポート**: 原文とリライトを**横並び＋数値ハイライト**で確認できる出力を生成。
5. **段階導入**: まず数機種でパイプライン検証→誤り0を確認→バッチ拡大。**一括本番リライトはしない**。
6. **完全再現性**: 生成は決定的(温度固定/プロンプト固定)＋原文ハッシュ記録で、いつでも再検証・巻き戻し可能。

> この章の要件を満たさない限り、リライト結果は本番に載せない。**「読みやすさ」より「情報の正しさ」が常に優先**。

## 5. 情報アーキテクチャ（機種統合設計）
### 5.1 統合機種レジストリ
- 2ソースの機種を**名称正規化＋別名/愛称で自動マッチング**して1つに統合。
  - 研究所由来の `slolabMachineData`(291機種・**別名/愛称/メーカー付**)をマッチングの辞書に活用。
  - マッチ確度が低いものは**保留リスト**に出し、人手確認（誤統合を防ぐ）。
- 各統合機種は「どのソースにあるか(期待値◎/研究所◎/両方)」を保持し**出典バッジ**で明示。

### 5.2 機種ページ = 4タブ（1機種1ページ）
| タブ | 内容 | 主な出典 |
|---|---|---|
| **狙い目** | 期待値表＋計算ツール、ゾーン/天井/ヤメ時、ハイエナ狙い目 | 期待値+研究所 |
| **解析・設定判別** | スペック、機械割、設定差、判別要素 | 期待値+研究所 |
| **大量集計** | ゾーン当選率・サンプル集計（コラム本文の表を集約） | 研究所 |
| **コラム** | 実戦/考察/座談会 等の関連記事一覧 | 研究所 |
- 各タブ内で**両ソースの内容をセクション統合**し、重複は片方に寄せ、差異は併記。**出典を各ブロックに明記**。

### 5.3 グローバル構造
- トップ = 機種グリッド（サムネ・新台フィルタ・検索）
- 横断検索（機種＋記事、別名/愛称対応）
- お気に入り（端末ローカル）
- ツール（計算/下振れ/ロガー）
- 記事一覧（カテゴリ絞り）

## 6. 機能要件
- **機種一覧**: サムネ・新台バッジ・機種名/別名検索・お気に入り★・カテゴリ/メーカー絞り。
- **機種ページ**: 4タブ、期待値表(原文搬送)、計算ツール、出典バッジ、関連コラム。
- **横断検索**: 機種名・別名・愛称・記事名。オフライン索引(JS)。
- **期待値計算ツール**: 両サイトの計算機能を統合（機種選択→期待値算出）。データは原文の`labelList2`等を保持。
- **下振れシミュレーター**: 期待値サイト由来（正規分布/試行）を移植。
- **稼働ロガー**: 期待値サイト由来（収支記録・端末ローカル保存）を移植。
- **大量集計ビュー**: コラム内の集計表を機種単位で集約表示。
- **記事ビューア**: リライト本文＋（トグルで）原文表示、出典・日付・カテゴリ。
- **お気に入り/最近見た**: localStorage。
- **PWA**: オフラインプリキャッシュ（機種/記事HTML・索引・ツール）。
- **PINゲート**: `0807`（現行djb2方式踏襲）。noindex+robots。

## 7. コンテンツ要件（リライト）
- 対象: 全記事本文＋機種解析の説明文。**表・数値・ツールデータは原文搬送（4章）**。
- 方針: 見出し/導入/用語の統一、冗長圧縮、表記ゆれ吸収、機種ごとの**要点サマリ(新規追加・数値は原文由来のみ)**。
- **情報不変の自動検証ゲート(4.3)を全記事に適用**。不合格は原文採用。
- 用語辞書(スルー/ゾーン/期待値/据え置き 等)を整備し統一。

## 8. デザイン要件（smartconnectデザイン言語）
- 配色: Blue `#0068B7`→Teal `#00A5AE`→Green `#2EAE6D` グラデ、墨`#1A2B4A`、地`#F6F9FC`、線`#E1E8F0`。
- フォント: Noto Sans JP（見出し900）＋Poppins（英字/数字）。
- 質感: 淡い影(≤0.10)、角丸(ボタン12/カード18-20)、hover`translateY(-3px)`、reveal 0.7s。
- **AI感回避**: 紫/ピンク不使用、Montserrat不使用、余白を効かせる、装飾はSVG blob/ドット/グラデ線のみ、非対称レイアウト。
- レスポンシブ（モバイル最優先＝ホール利用）、`prefers-reduced-motion`対応、focus可視、コントラスト確保。
- 参照: `~/smartconnect/hp/css/renewal.css`（本命実装）、`smartconnect-systems/docs/design-research.md`（定石/ジャンプ率）。

## 9. 技術要件
- **Next.js (App Router) + `output: 'export'`（完全静的出力）** / TypeScript / Tailwind / **shadcn/ui**(lucideアイコン)。
- データは**ビルド時ローカルJSON**（2ソースをマージした統合データ）。サーバ無し。
- ツール(計算/下振れ/ロガー)は**クライアントReactコンポーネント**（静的でも動作）。
- 画像=**Cloudflare R2**（既存の仕組み流用、`IMG_BASE`相当をNext画像パスに適用、非最適化=`unoptimized`）。
- **PWA**（SW precache: next-pwa 等 or 手書きSW）。PINゲート（クライアント）。
- 配信=**GitHub Pages**（`out/`をActionsでデプロイ）。noindex/robots。
- リポジトリ: 新規 `suro-hub`（作業ディレクトリ `/Users/ijichiyuuta/.superset/projects/suro-hub`）。

## 10. データ統合設計
- 入力: 
  - 期待値: `smartslotgoal/scraper/data/json/{machines,news,pages}.json` + `dash.json`
  - 研究所: `slolabo/data/json/{posts,pages,categories,tags}.json` + `machines.json` + `machine-directory.json`(別名辞書) + `img-map.json`(画像→R2)
- 処理: 名称正規化→機種マッチング→統合機種JSON生成→タブ別コンテンツ割当→出典付与→（リライト層を後段で合流）。
- 出力: `data/unified/*.json`（機種・記事・索引）。**原文は`source-original/`に凍結**。

## 11. 更新・運用（1本化）
- 統合更新スクリプト: 
  1. 各ソース取得(現行 fetch 群を流用) → 2. データ統合 → 3. リライト差分適用(検証ゲート通過分のみ) → 4. Next build/export → 5. 画像R2アップロード差分 → 6. push(GitHub Pages)。
- 研究所側の**アカウント削除リスク**を考慮し、統合データは**手元完結**（凍結原文＋画像ローカル）を維持。
- PINや秘密情報は非コミット（`.gitignore`厳守）。

## 12. 非機能要件
- パフォーマンス: 初回表示軽量、機種/記事はプリキャッシュでオフライン即時。画像はR2+lazy。
- 可用性: 完全静的＝依存最小。元サイト消滅後も閲覧・大半の更新運用が成立。
- セキュリティ/プライバシー: noindex+robots+PIN、認証情報/セッション非コミット。
- 保守性: データとデザインを分離、統合ロジックとリライトを疎結合、決定的生成で再現可能。
