## 2. 機種マッチング仕様（実測で確定）
### 2.1 正規化 `norm(s)`
1. Unicode `NFKC`（全角→半角、互換文字統一） → 2. 小文字化 → 3. **カナ統一（カタカナ⇄ひらがな）** → 4. **英数・かな・漢字以外を全除去**（絵文字🆕/記号/空白/中黒/`ー`）。
   - カナ統一により「グール」＝「ぐーる」、「リゼロ」＝「りぜろ」等が一致。
2. **接頭辞除去** `stripPre`: 先頭の `スマスロ/スマパチ/パチスロ/L/S/A` を除去した別キーも生成（両ソースに適用）。

### 2.2 別名辞書の活用
研究所 `machine-directory.json` の **正式名＋別名(読み)＋愛称** を全て正規化して逆引き表(約1,936鍵)を構築。メーカー名も保持。

### 2.3 多段マッチ（確度つき）
| 段 | 方法 | 実測結果(期待値 機種151件) |
|---|---|---|
| ① 確実 | `norm` / `stripPre` 完全一致（辞書含む） | **129件** |
| ② fuzzy | 一方が他方を包含(4文字以上)・要確認 | **17件**（全て正解を確認・下記） |
| ③ 未マッチ | いずれも該当なし＝新規 or 表記差 | **5件** |
- **①は自動採用。②③は「保留リスト(22件)」として人手確認**（誤統合を防ぐ＝情報整合性の一部）。

### 2.5 記事・ツールの分離（16件）
期待値の`type:"machine"`だが実体は記事/ツールのもの（「設定狙い」「各サブスク(note)紹介」「S沖ドキGOLD実践値シミュレーター」「転生シャッター狙い実践データ」「北斗の拳スロ塾流無想転生打法」等）は**機種ではなく記事/ツールへ再分類**。判定=タイトルに `狙い/実践/考察/シミュ/紹介/について/履歴/打法/データ` 等を含む＋人手確認。

### 2.7 検索仕様（★本人要望: 読み・略称でヒット）
- **正規化＝2.1（NFKC＋カナ統一＋記号除去）** を検索クエリと索引の両方に適用。
- 索引キー＝各機種の **正式名＋別名＋読み＋愛称**（辞書由来）。クエリが**いずれかの部分列に含まれれば命中**。
- **実証済**: 「グール」/「ぐーる」→ `L東京喰種`（別名「とうきょうぐーる/トーキョーグール」・愛称「金木/ぐうる」経由）。他「北斗/ほくと」「リゼロ」「バジリスク」「えヴぁ」等も命中。
- ランキング: 完全一致＞前方一致＞部分一致 の順で上位表示（ノイズ低減）。記事名も同索引に含める。
- 索引はビルド時に静的生成（`unified/search-index.json`）＝**オフラインでも動作**。

## 3. 統合スキーマ
### 3.1 統合機種 `unified/machines.json`
```jsonc
{
  "id": "l-hokuto-tensho2",              // 正規化slug（安定・URL用）
  "name": "L北斗の拳 転生の章2",          // 表示名（正式名を採用）
  "aliases": ["北斗","ほくと","転生2"],    // 検索用（辞書由来）
  "maker": "サミー",
  "thumb": "img/xxxx.jpg",               // R2配信キー
  "isNew": true,
  "sources": { "ev": true, "lab": true },// 出典（両方/片方）
  "match": { "confidence": "exact|fuzzy|manual", "reviewed": true },
  "tabs": {
    "nerai":   [ /* 狙い目パターン配列(下記) */ ],
    "spec":    [ {"src":"ev","html":"…"}, {"src":"lab","postId":485680} ],
    "shukei":  [ {"src":"ev","kdashUrl":"…"}, {"src":"lab","postId":485679} ],
    "columns": [ {"src":"lab","postId":521704}, … ]
  }
}
```
- **★狙い目は「条件の種類」が可変（2026-08-02 本人指摘）**: ゲーム数だけでなく **スルー回数 / 状態(リセ後・AT後・チャンスモード後 等) / モード** など、機種ごと・狙い方ごとに条件軸が違う。→ `nerai` は **狙い目パターンの配列**とし、各パターンが自分の条件種別を持つ:
```jsonc
"nerai": [
  { "title":"天井狙い",   "condType":"現在ゲーム数", "src":["ev","lab"],
    "rows":[ {"cond":"500G〜","ev":"+380円","hourly":"—"}, … ] },
  { "title":"スルー狙い", "condType":"スルー回数",   "src":["lab"],
    "rows":[ {"cond":"2スルー〜","ev":"+900円","hourly":"+2,300"}, … ] },
  { "title":"リセット後", "condType":"状態/経過",     "src":["ev","lab"],
    "rows":[ {"cond":"設定変更後 0G〜","ev":"+120円"}, … ] }
]
```
  表の1列目ヘッダ＝`condType`（可変）。数値・条件は原文由来のまま（情報不変）。抽出時に期待値`nerai_html/tenjo_html`＋研究所`sections.nerai`本文から**パターン単位でパース**（ゲーム数表/スルー表/状態別を判別）。
- **タブ割当ルール**:
  - 狙い目 ← 期待値`nerai_html`＋`tenjo_html` ＋ 研究所`sections.nerai`本文（**上記パターン配列に整形**）
  - 解析・設定判別 ← 期待値`kaiseki_html` ＋ 研究所`sections.spec`本文
  - 大量集計 ← 期待値`kdash_url`(集計ダッシュ) ＋ 研究所`sections.shukei`/集計コラム
  - コラム ← 研究所`otherIds`（関連記事）
- 各ブロックは`src`(出典)を保持し、UIで**出典バッジ**表示。重複内容は片方に寄せ、差異は併記。

### 3.2 統合記事 `unified/articles.json`
```jsonc
{ "id":"…", "title":"…", "machineId":"l-hokuto-tensho2|null",
  "source":"ev|lab", "category":["ハイエナ","コラム"], "date":"…",
  "originalHtml":"…(凍結原文)", "rewrittenHtml":"…(検証通過後のみ)",
  "rewrite":{ "status":"pending|passed|review", "checkedAt":"…", "srcHash":"…" } }
```

### 3.3 原文凍結 `source-original/`
- 全記事・機種本文の`content.rendered`(原文)を**不変保存**＋SHA。リライトは`rewrittenHtml`に別持ち。検証・巻き戻しの根拠（憲章 4.3-①）。

## 4. 出典モデル
- 機種/ブロック単位で `ev`(期待値) / `lab`(研究所) / `both` を保持。
- UI: 「出典: 期待値◎ 研究所◎」バッジ。両方ある狙い目は統合し、数値が食い違う場合は**両方併記＋出典明記**（勝手に一方採用しない＝情報を消さない）。

## 5. 出力物（M5で生成）
```
data/unified/
 ├ machines.json      // 統合機種(約290)
 ├ articles.json      // 統合記事(≈1,795+期待値記事)
 ├ search-index.json  // 機種名/別名/記事名
 ├ review.json        // 保留リスト22件＋記事再分類16件（人手確認用）
 └ img-map.json       // 画像→R2キー（研究所分流用＋期待値分マージ）
source-original/       // 凍結原文（不変・SHA付）
```

## 6. マッチング処理フロー（実装方針・M5）
1. 期待値・研究所・辞書を読込 → 2. 記事/ツール分離(2.5) → 3. norm＋辞書で多段マッチ(2.3) →
4. ①自動統合／②③は`review.json`へ → 5. 人手確認結果を`overrides.json`に記録(再現性) →
6. タブ別にコンテンツ割当＋出典付与 → 7. 原文凍結 → 8. `unified/*`出力。
- **overrides.json**（手動確定の統合/分割）で決定を固定＝毎回の更新でも安定・再現可能。

## 7. 確定事項（2026-08-02 本人承認）
1. **統合ルール**: **同一機種は必ずまとめる**（読み/別名一致も同一とみなし統合）。無印 vs 2/最終章など**本当に別台のものだけ別機種**。判定に迷うものは保留リストで確認。
2. **保留22件・再分類16件・読み一致統合**: **M5実装後に一覧を出して一緒に確認**（人手確定を`overrides.json`に固定）。
3. **表示名＝正式名称**（研究所の正式名）。期待値名・略称・読みは**別名として検索に保持**。
4. **検索**: 読み・略称・カタカナ/漢字どちらでもヒット（2.7、グール→東京喰種 実証済）。
